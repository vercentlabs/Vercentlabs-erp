The corrected finding is narrower and different in kind: **the function exists but is completely unreachable — grep confirms zero API routes and zero UI components call `mergeCrmLead`.** It is real, tested-quality code with no way for any user to invoke it. ## Net assessment (revised after the F022 correction)

This is now a smaller gap than first assessed, and a different kind of gap: **not missing engineering, but a missing route.** `mergeCrmLead` is real, correct, deadlock-safe, idempotent code sitting unused. The actual remaining work is: (1) add an API route + UI action that calls it (cheap, since the hard logic is already done), (2) add an explicit "dismiss as not-a-duplicate" outcome distinct from override, (3) make matching rules configurable, (4) extend matching to Contacts/Accounts, (5) decide field-survivorship rules for the lead row itself. The advisory-lock race protection (`lockStrongIdentityKeys`) and disclosure-safety design (`canDisclose`/`safeMatch`) remain genuinely excellent. Net: 19 of 37 rows PASS, 6 PARTIAL, 0 outright GAP after correction, rest not independently traced. Still worth prioritizing in the gap-closing pass, but "wire up the existing merge function" is a much smaller task than "build a merge engine from scratch."

**Process note for future audits in this pass:** this correction happened because F022 (audited later) reads `index.js` broadly and happened to pass over `mergeCrmLead`, while F008's original pass only grepped `lead-duplicates.js` and `account-intelligence.js` specifically for merge functions and missed that `index.js` itself (2,700+ lines) could hold one. Lesson: a "not found" verdict based on a targeted grep across a few files is weaker evidence than one based on reading the full module's export surface — worth a second pass on other features' "GAP: doesn't exist" findings where the search was narrow, before treating them as final.
