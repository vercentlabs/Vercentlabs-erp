## Net assessment (updated 2026-09-05)

29 of 37 rows now PASS. The one genuine gap — no admin-configurable qualification-criteria system — is fixed, and made a real, reachable resource rather than orphaned configuration (see the F028 correction below this was checked against). This is otherwise one of the more tightly-built features in the audit: correct concurrency locking, correct requalification-as-distinct-event semantics, and a genuinely stricter-than-baseline permission gate on viewing qualification data.

**Side discovery while wiring the new resource:** confirming how to properly expose `qualification-criteria` required tracing the real UI-reachability chain (`CRM_UI_RESOURCE_KEYS`/`CRM_API_RESOURCE_KEYS` in `scope.ts`, plus the hand-curated link list in `crm/settings/page.tsx` — not the unused `CRM_SETUP_RESOURCE_KEYS`). Doing that revealed F028's `custom-field-definitions`/`custom-records` admin form (added to `apps/web/src/modules/crm/index.ts` during F028's gap-closing work) is **not in any of those lists and has zero route referencing it anywhere in `apps/web/src/app`** — it is real, correct domain-layer code (verified directly by tests calling `createCrmRecord`/`updateCrmRecord`), but its admin UI is currently unreachable by any live page. This doesn't affect F028's actual fixes (dependent options, required-field rollout), which work correctly for any caller including a future UI or a direct API consumer — but the admin form itself needs the same `scope.ts`/settings-page wiring this fix just did for `qualification-criteria` before an admin can reach it in a browser. Flagging as a follow-up, not fixing inline (out of scope for F006).
