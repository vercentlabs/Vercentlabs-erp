It was reachable only through a manual `POST .../lead-intelligence/sla {action:"scan"}` action with no scheduled tick ever calling it. Added `crm.automation.detect_lead_sla_breaches`, a new worker tick mirroring `crm-automation-overdue.js`'s exact pattern (same naturally-idempotent status-transition guarantee, so no new idempotency mechanism was needed), registered in the scheduler alongside the existing overdue-activity tick. All three fixes have real regression tests: 15 new backend cases (5 for the SLA scan handler/domain function combined, 10 for availability/fallback) plus 3 new web wiring assertions. |
