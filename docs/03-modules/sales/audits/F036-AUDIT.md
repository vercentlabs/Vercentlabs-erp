| ID | Verdict | Evidence |
|---|---|---|
| FLOW-001 (lifecycle) | PASS | Real state machine, each transition individually guarded: `submitQuotation` only from `draft`; `approveQuotation` only from `pending_approval` **and** only if `current_version_id` still matches the version the approval was requested against (stale-approval invalidation — a revision after submission invalidates the pending approval, not just cosmetically); `sendQuotation` only from `approved`; `reviseQuotation` blocked once `accepted`/`converted`/`cancelled`. | APP-001 (stale-approval invalidation) | PASS | Two independent mechanisms: `approveQuotation`'s version-id match (above), and `reviseQuotation` explicitly cancels any `pending` `approval_requests` row for the quotation with `decision_note='Quotation was revised.'` — a revision can't leave a stale approval floating that later gets approved against superseded content. |

## Net assessment (2026-09-06)

This is the strongest-evidenced feature in Sales so far — a real, guarded state machine, a genuine configurable approval-threshold engine with stale-approval invalidation via two independent mechanisms, hashed expiring public tokens, and idempotent quotation-to-order conversion reusing the same pipeline as direct order creation. Only gap found is the pagination/truncation issue already tracked under the shared Sales gap-closing item (extends it to `listQuotations`, not a new item).
