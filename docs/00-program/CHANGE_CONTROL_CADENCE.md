# Change Control Cadence

- Canonical F-ID/name/range/count changes require founder approval and a recorded decision.
- Requirement changes after architecture freeze require impact analysis across capability, journey, data/API, tests/UAT, migration and release plan.
- P0/P1 architecture/security/accounting/payroll/inventory/tax changes require red-team review before merge.
- Every implementation wave closes with a scope/decision/audit-register reconciliation.
- No AI-generated change may silently modify canonical requirements or mark readiness without validator evidence.
