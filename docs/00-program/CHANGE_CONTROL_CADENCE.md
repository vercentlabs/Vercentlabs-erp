# Change Control Cadence

This control is **event-driven**, not calendar-driven.

- Canonical F-ID/name/range/count changes require Project Manager approval and a recorded decision.
- Requirement changes after architecture freeze require impact analysis across capability, journey, data/API, dependency sequence, cost/procurement, tests/UAT, migration and release plan.
- P0/P1 architecture/security/accounting/payroll/inventory/tax changes require a deliberate red-team review lens before Project Manager acceptance.
- Every implementation wave closes with scope/decision/RAID/cost/evidence reconciliation before a successor wave is opened.
- No AI-generated change may silently modify canonical requirements, assign work to another person, invent a timeline or mark readiness without validator evidence.
