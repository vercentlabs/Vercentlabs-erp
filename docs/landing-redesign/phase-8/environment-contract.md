# Phase 8 Environment Contract

Every environment variable `apps/landing` actually reads, verified via a repo-wide grep for `process.env.` (not inferred from `.env.example` alone — `.env.example` is the documentation, this table is the audited ground truth it should match).

| Name | Required? | Server/Client | Secret/Public | Default allowed? | Dev value | Production requirement | Validation | Failure behavior |
|---|---|---|---|---|---|---|---|---|
| `NEXT_PUBLIC_SITE_URL` | Yes (for a correct production deploy) | Both (baked into client bundle at build time — `NEXT_PUBLIC_*` prefix) | Public | **Yes, falls back to `http://localhost:3000`** | Unset, or the real dev URL | Must be set to `https://www.vercentlabs.com` (or the real final domain) | None — `new URL()` throws on a malformed value, so a garbage string fails loudly at build/boot; a *missing* value does not fail, it silently uses localhost | **Silent wrong-value risk**: if unset in production, every canonical URL, sitemap entry, OG image URL, and JSON-LD `url` field would read `localhost:3000` instead of the real domain — a real, high-impact SEO defect if forgotten. See `search-launch-audit.md`'s BLOCKER note. |
| `NEXT_PUBLIC_APP_URL` | Yes (for a correct production deploy) | Both | Public | **Yes, falls back to `http://localhost:3001`** | Unset, or the real dev URL | Must be set to the real `app.vercentlabs.com` (or equivalent) origin | Same as above | Same silent-localhost risk — affects the header/footer "Sign in" link destination. |
| `CRM_CAPTURE_FORM_KEY` | Yes, for lead delivery to function | Server-only | Public-shaped value (a UUID identifying which org's CRM receives leads) but treated as sensitive configuration, not published | **No** — `lib/crm-capture.ts` throws a clear, loud error if unset (`deliverDemoRequest` fails immediately rather than silently no-op'ing) | Set locally to a real synthetic-org form key (see `apps/landing/.env.local`, gitignored) | Must be set to whatever real organization Vercentlabs sales designates to receive marketing leads | `.trim()`'d before use; empty/whitespace-only is treated as unset | **Fails loud, not silent** — confirmed via Phase 7's own testing: with this unset, `/api/book-demo` throws immediately rather than accepting a submission it can't deliver. This is the correct behavior; no change needed. |
| `CRM_CAPTURE_PROXY_SECRET` | Yes, for lead delivery to function | Server-only | **Secret** — the HMAC signing key for the CRM capture request | **No**, same throw-on-unset behavior as above | Set locally, gitignored | Must match the exact value configured in `apps/web` for the same form | `.trim()`'d before use | Same fail-loud behavior. **Never exposed to the browser** — confirmed via a repo-wide grep: it's read only in `lib/crm-capture.ts` (a server-only module, never imported by a Client Component) and never appears in any client bundle output. |
| `NODE_ENV` | Implicit (set by the runtime, not by a human) | Both | Public (not sensitive) | Yes — Next.js sets this automatically for `build`/`start`/`dev` | `development` | `production` (set automatically by `next build`/the standalone server, not something a human sets manually) | N/A | N/A |
| `PORT` / `HOSTNAME` | Only relevant to the standalone server's own boot, not read by any application code via `process.env` | Server process only | Public | Yes — Next.js standalone server defaults to `PORT=3000`, `HOSTNAME=0.0.0.0`/localhost depending on version | `3050` in this phase's testing (a deliberately non-default port — see `phase-7/decision-log.md` item 8) | Whatever the real hosting platform's port-binding convention requires | N/A | If the port is already in use, the server fails to bind and exits — observed directly this session multiple times. |

## No production-critical config silently falls back to something unsafe — mostly true, with one real caveat

Every server-only secret (`CRM_CAPTURE_FORM_KEY`, `CRM_CAPTURE_PROXY_SECRET`) **fails loudly** if missing — confirmed behavior, not assumed. The one real gap: **`NEXT_PUBLIC_SITE_URL`/`NEXT_PUBLIC_APP_URL` silently default to `localhost`** if forgotten in a real production deployment. This is the single most important environment-contract risk in this application — see `search-launch-audit.md` and `launch-readiness-scorecard.md` for how this is tracked as a launch gate.

## No secret value is documented here

Per this workstream's own instruction, no real secret value appears in this document or anywhere in this phase's docs — only the *shape* and *requirement* of each variable.

## Environment variables NOT used by `apps/landing`

For completeness/contrast: `apps/web`'s `.env.example` (a different app in this monorepo, out of this phase's scope) has a much larger surface — `DATABASE_URL`, `SESSION_COOKIE_NAME`, `SMTP_*`, etc. None of these apply to `apps/landing`, which has no database, no session/auth system, and no server-side email sending of its own.
