## Cycle 2 — four parallel specialist reviewers against the live build

Dispatched UX/CRO, SEO/AEO/GEO, brand/design, and frontend-quality reviewers in parallel against the running production server, each explicitly instructed to verify finding currency (capture timestamps / live-server re-verification) before reporting — per this phase's own brief, since Phase 4 had a real stale-finding incident. All four reviewers took this instruction seriously: the brand/design reviewer explicitly discarded the pre-supplied screenshot set (found their timestamps predated the current server instance) and re-captured live instead; the UX/CRO reviewer found the server down mid-review and restarted it before continuing.

### Findings, triaged

**Fixed this cycle (10 items):**

1. **[Critical, brand/design]** `Grid columns={12}` had no responsive fallback (`grid-cols-12` with no `sm:`/mobile collapse), causing `/implementation` to balloon to ~21,425px on mobile with overlapping, one-word-per-line text. Fixed in `components/layout/container.tsx` (`"grid-cols-1 sm:grid-cols-12"`, matching the `2`/`3`/`4` variants' existing pattern). **Verified**: re-captured `/implementation` mobile — height dropped to ~5,900px CSS pixels, all 8 phases render cleanly with no overlap.
2. **[Critical/High, converged — both brand/design and SEO/AEO/GEO independently found this]** Every `/solutions/*` and `/workflows/*` page rendered the exact same sentence twice in a row (hero subhead, then the `DirectDefinition` section immediately below it) — both used `problemStatement`/`summary` for both slots. Fixed by adding a distinct `directDefinition` field to all 5 solutions and all 6 routed workflows (matching the pattern industries already used correctly: `directDefinition` for the hero, `operatingModel` for `DirectDefinition`), with a new content test (`solution-content.test.mjs`, `workflow-content.test.mjs`) asserting the two fields are never textually identical.
3. **[Objective, UX/CRO]** Primary nav had grown from the IA doc's documented 5 top-level items to 7 (Solutions and Workflows added as flat top-level links). Fixed by folding Solutions and Workflows into the existing Product mega-menu's children instead, restoring the documented 5-item top-level structure (Product, Modules, Industries, Pricing, Resources).
4. **[Moderate, SEO/AEO/GEO]** 3 of 4 industries (distribution, retail, professional-services) had only 3 FAQs, below `seo-aeo-geo-architecture.md`'s documented 4-6 floor. Added one real, grounded FAQ to each; strengthened the content test from `>= 2` to `4-6` exactly.
5. **[Low-Moderate, SEO/AEO/GEO]** `/solutions/connect-business-operations` had two FAQs in tension: one correctly caveated that Stock isn't yet automatically integrated with standard sales-order fulfillment, the next implied Stock was fully connected alongside CRM/Sales/Procurement/Accounting. Fixed by removing Stock from the second FAQ's claim and cross-referencing the caveat.
6. **[Low, SEO/AEO/GEO]** The `hr-payroll-dashboard` screenshot's `workflow` metadata tag pointed to `payroll-to-books` (an unrouted, near-duplicate workflow entry) instead of `hire-to-payroll` (the actual routed workflow it illustrates). Fixed the tag in `lib/product/screenshots.ts`.
7. **[Low, SEO/AEO/GEO]** `LANDING_ICPS`'s `industrySlug: "distribution-retail"` pointed to a route that no longer exists post-split — a landmine for any future code naively building a link from it, though nothing currently renders one. Fixed by converting to `industrySlugs: string[]` (`["distribution", "retail"]` for ICP 2), with a new test asserting every ICP's `industrySlugs` resolve to real routes.
8. **[Real gap, UX/CRO — partially stale, see below]** `docs/landing-redesign/phase-5/decision-log.md` did not yet exist when the UX/CRO reviewer checked for it (written later in the same session, while all 4 reviewers were running in parallel — see "stale-finding reconciliation" below) — but the reviewer's underlying point about workflow-selection deviation from `phase-4/phase-5-brief.md`'s own route list was real and had not been explicitly written down anywhere. Added `decision-log.md` item 8 explaining why `order-to-fulfilment`/`hire-to-payroll` shipped instead of `quote-to-order`/`inventory-to-replenishment`.
9. **[Moderate, frontend-quality]** `RolePerspective` and `RecommendedModuleStack` both skipped from `h2` to `h4`, breaking the heading-outline convention every sibling Phase 5 component correctly follows (`h3`). Fixed both to `h3`.
10. **[Real, exploitable, frontend-quality]** `analytics-events-sync.test.mjs`'s regex only matched double-quoted string literals — the reviewer demonstrated a single-quoted entry parses as zero matches, silently passing all 82 tests with an untracked event. Fixed by broadening the regex to both quote styles and adding an explicit assertion rejecting single-quoted entries outright. Reproduced the reviewer's exact exploit against the fix to confirm it's now caught (see `decision-log.md` item 6's update).

**Also fixed, smaller/consistency items surfaced alongside the above:**

- `/book-demo?module=` never set a `contextLabel`, unlike the 3 newer params — added one for consistency (UX/CRO finding 4).
- `order-to-fulfilment`'s new `directDefinition` was deliberately worded to reinforce its distinction from `lead-to-cash` (warehouse/fulfilment focus vs. revenue-team focus) rather than restate shared sequence steps — a partial mitigation of the SEO reviewer's real "content overlap" finding (see Deferred below for what remains unaddressed).
- `/solutions/multi-company-management`'s `problemStatement`/`directDefinition` now explicitly anchor to ICP1's "several facilities" and ICP2's "multiple warehouses" language, addressing the UX/CRO finding that it didn't clearly map to any documented ICP.

### Stale-finding reconciliation

Per this phase's explicit instruction to check finding currency before accepting it: the UX/CRO reviewer's finding 2 stated `docs/landing-redesign/phase-5/decision-log.md` "does not exist anywhere." At the time that reviewer checked, this was **true** — the file was written later in the same session, concurrently with the 4 reviewers running in the background (the same class of timing artifact Phase 4 hit once). Rather than dismiss the finding as simply stale, it was checked against the *current* file: `decision-log.md` now exists and covers items 1-7, but genuinely did not yet cover the specific workflow-route-selection deviation the reviewer's finding was really about — so the finding was neither fully stale nor fully current; the real, remaining sub-point was extracted and addressed (item 8 above), rather than the whole finding being either blindly re-fixed or blindly dismissed.

### Deferred, documented, not silently dropped

- **[High, brand/design]** Solution-page heroes never show a dedicated screenshot (solutions are cross-cutting, no single representative screen exists) — falls back to the "Built into" module-tag pattern, which is honest and real but visually thinner than an industry/workflow page's hero. Not fixed this cycle: the two real options (author a `heroScreenshotId` per solution, which risks a misleading module-to-solution pairing under the Evidence and Honesty Rules; or build a new pipeline-diagram visual) both need more design judgment than a Cycle 2 fix window allows. Flagged for Phase 6 or a dedicated follow-up.
- **[High, SEO/AEO/GEO]** `sitemap.ts` uses one global `lastModified` date across all 52 routes rather than a real per-page `lastReviewed` field. This is a carried-forward gap Phase 4's own decision-log already flagged ("worth introducing... so it doesn't have to be retrofitted a third time") and Phase 5 also didn't close — it would require adding `lastReviewed` to every content file across all 5 phases' worth of pages, a larger structural change than a Cycle 2 fix window allows. Still deferred, now flagged a second time.
- **[Moderate, SEO/AEO/GEO]** Real sequence-step wording overlap between `lead-to-cash` (steps 6-8) and `order-to-fulfilment` (steps 1-2, 5) — both describe order conversion, credit check, and invoicing in near-identical language. Partially mitigated via the new `directDefinition` fields explicitly framing the two pages' distinct angles (revenue-team origination vs. warehouse/fulfilment execution), but the underlying sequence-step text itself was not restructured. A deeper fix (trimming one page's overlapping steps to link to the other instead of restating them) is a real, worthwhile follow-up not completed this cycle.
- **[Critical-severity-if-isolated, UX/CRO, but pre-existing and site-wide, not a Phase 5 regression]** The persistent header "Book a Demo" CTA is hidden below 480px (`hidden sm:block`), leaving only a hamburger-buried CTA on most phones — a direct violation of `conversion-architecture.md`'s "must never require opening the mobile nav" rule. This predates Phase 5 (present since Phase 2/3's header) and was not introduced this phase, but Phase 5's now-9-item Product mega-menu (after folding in Solutions/Workflows, see fix 3) does make the mobile nav panel longer to scroll through. A real, high-priority fix — but a header-architecture change (a bottom-anchored persistent mobile CTA bar, independent of hamburger state) is a bigger structural change than a content-and-linking phase's Cycle 2 window should absorb. Flagged prominently for immediate follow-up, not silently carried forward a third time.
- **[Judgment call, brand/design]** `/industries`, `/solutions`, `/workflows` index pages use a copy-only hero (no screenshot or diagram) before their list — the reviewer's own assessment was this is defensible for a hub/index page type, with `WorkflowConnector` (already built, used on the homepage) as a candidate visual anchor for `/workflows` specifically if a future pass wants one. Not treated as a defect requiring immediate action.
- **[Pre-existing, not a Phase 5 regression]** `ProductCallout` (numbered in-image callouts) still unused on any live screenshot (Phase 4 decision-log item 10 already deferred this); a raw-precision value visible in the `sales-order-detail` screenshot on `/workflows/lead-to-cash` (a screenshot-curation note, not a fabrication issue); title-pattern deviation from the documented 3-segment spec (present since Phase 4, not introduced this phase).
