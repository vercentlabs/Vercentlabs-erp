# Phase 7 WCAG 2.2 AA Matrix

Automated tooling (axe-core, 13 routes, zero serious/critical violations — see `accessibility-audit.md`) is necessary but explicitly insufficient on its own; every row below reflects either a real automated test, a real manual/scripted keyboard check performed this phase, or an explicit statement that a criterion wasn't manually verified.

## Explicit limitations (stated, not hidden)

- **No real screen reader was used.** See `accessibility-audit.md`'s dedicated section — DOM/accessibility-tree inspection via axe-core substitutes, with this limitation stated plainly.
- **200% zoom / desktop reflow was not formally tested this phase** — the mobile-conversion test suite covers 320-412px width reflow (a real, common failure mode this codebase now has regression protection for), but a dedicated 200%-browser-zoom-at-desktop-width test was not built. Recorded as a `phase-8-brief.md` follow-up.
- **Not every one of the site's 74 indexable routes was individually tested** — 13 representative routes were chosen per the governing brief's own sampling strategy (deep review on representative routes, broader smoke coverage on the full route suite via `phase5-routes.spec.ts`/`phase6-routes.spec.ts`/`module-routes.spec.ts`).
