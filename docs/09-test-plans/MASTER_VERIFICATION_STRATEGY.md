# Master Verification Strategy

Verification layers: unit/domain; property/invariant; database/RLS; API/contract; authorization-negative; integration; idempotency/retry/fault injection; reconciliation; migration; performance; accessibility; browser/device E2E; human UAT; operational restore/DR.

A test ID in documentation represents a planned verification obligation until implementation evidence links it to an executable test/result. Planning traceability must never be confused with test execution.
