## Traceability methodology (honest disclosure)

`docs/frontend-rebuild/CRM_REQUIREMENT_TRACEABILITY.csv` is generated by
`scripts/validation/generate-crm-traceability.mjs` from the canonical
`SUBREQUIREMENT_REGISTER.csv`, joined with hand-curated evidence in
`docs/frontend-rebuild/CRM_TRACEABILITY_OVERRIDES.json`. Two things to
know before trusting a row:

1. **`requirement_classification`** (DIRECT_UI / AFFECTS_UI_STATE /
   NO_DIRECT_UI) defaults from a documented `requirement_type` heuristic
   (UX/US/APP → DIRECT_UI; FR/FLOW/E2E/UAT/NOTIF/REP → AFFECTS_UI_STATE;
   BR/VAL/CALC/AUTO/SEC/DATA/API/INT/OBS/PERF/AI/CAP → NO_DIRECT_UI) —
   it is **not** a per-row read of all 1,110 normative statements. Treat
   it as a reasonable default, not a certified classification, for any
   feature not listed below as hand-verified.
2. **`implementation_status`** defaults to `NOT_STARTED` for every row.
   It only reflects real evidence for features listed in the status
   table below as IMPLEMENTED or IN_PROGRESS, via entries in the
   overrides file.

## Discovered backend gaps (fixed this pass)

- `apps/web/src/app/api/crm/leads/[id]/assign/route.ts` and
  `.../stage/route.ts` were wrapping the backend's real result objects
  under a misleading `record` key instead of returning them as-is —
  fixed (see git log, commit `9d8d4514` and the commit before it).
- `EnterpriseDataGrid`'s row-selection checkbox click bubbled to the
  row's own `onRowClick`, so selecting a row also navigated away from
  the list — fixed in `packages/design-system` (affects every future
  module, not just CRM).
- The Lead frontend referenced a nonexistent `qualificationStatus` field
  (the real backend column is `qualification_state`) — the qualification
  badge always silently showed the fallback value. Fixed.
